## 当前两个问题的解释

### Owner 登录缺少普通入口

已确认后端 `POST /api/auth/owner/login` 存在：校验服务器OWNER_ACCESS_SECRET后创建数据库会话，发送HttpOnly、Secure、SameSite=Lax Cookie。现有Owner会话默认30天。它不是用户名/密码账号模型，也没有常规Owner登录表单。

`apps/web/src/features/settings/account/account-settings-panel.tsx` 的Guest表单只兑换Pro共享访问码；Owner/Pro只展示身份和退出。源码注释明确说明Owner secret不放入设置页、只能调用原API。因此“账户”页可打开，但不能用它正常登录Owner；Pro共享码不能当Owner凭据。

任务AUTH-01不是继续要求在开发者工具注入Key，而是建立正常账号登录入口并复用现有服务端会话。AUTH-02负责账号初始化与忘记密码后的受控恢复，避免再次只能修改浏览器状态。

证据：[账户面板](../../apps/web/src/features/settings/account/account-settings-panel.tsx)、[登录API](../../apps/web/src/app/api/auth/owner/login/route.ts)、[会话Cookie](../../apps/web/src/server/auth/session-cookie.ts)、[现有会话存储](../../packages/db/src/access/index.ts)。

### About 被隐藏与404

已确认有两层独立原因：

- `apps/web/src/components/layouts/site-navigation.ts` 实际导航数组只有文档、路线图和仪表盘，没有About栏目。
- `/{locale}/about` 和 `/{locale}/about/activity` 都调用requireOwner；`apps/web/src/server/auth/guards.ts` 对非Owner调用notFound，因此Guest访问返回404。

只读公网实测：`/zh/about`=404、`/zh/about/activity`=404、`/zh/settings?section=account`=200。这与代码一致。About的Owner限制已在2026-07-27的70d8398提交中存在；本次部署没有新增封锁。新域名没有旧浏览器Cookie，迁移也明确排除了32条开发登录会话，因此更容易看见这个限制。

公开About不能只删除requireOwner后继续用Owner视角加载文档：现有路由会把Owner权限传给About文档loader，直接沿用可能扩大可读范围。需要用公开读取契约，审核About内容的发布/访问状态，活动使用单独的白名单汇总输出。`/api/internal/activity/*` 仍保持Owner；不要整体放开内部API。

证据：[导航](../../apps/web/src/components/layouts/site-navigation.ts)、[About路由](../../apps/web/src/app/%5Blocale%5D/about/page.tsx)、[活动路由](../../apps/web/src/app/%5Blocale%5D/about/activity/page.tsx)、[权限守卫](../../apps/web/src/server/auth/guards.ts)、[活动服务](../../apps/web/src/server/activity/github.ts)。

## 实施顺序和验收方式

第一轮：AUTH-01/02＋ACL-01，先建立可用账号、恢复入口和角色边界。第二轮：PUB-01/02/03，公开About及脱敏活动。BAK-01/02与ALT-01的目标选择同步讨论；目标齐备后优先完成备份/监控/报警闭环。再执行REP和UI整理，不将所有新功能一次塞入主机。

每项追加记录：结论/范围 → 改动与迁移 → 本地/隔离证据 → 确切构建与发布制品 → 生产实测 → 回退路径与遗留项。只有完成对应验收才能勾选；讨论决定、代码完成、隔离通过、真实接入分别记录。无目标/凭据时记录具体阻碍，不伪造完成。

下一轮优先讨论AUTH-01/02：单Owner账号的命名与初始化、登录页位置、改密/恢复、现有master secret的退出方式。无需在聊天提供用户名密码或新密钥。

### 新增与遗留问题登记（排入下一版本）

1. **UI-BUG-01 / P2：Windows Edge 密码输入框“双眼睛”图标**
   * **现象**：在 Windows Edge（Chromium）下，原生 `<input type="password">` 会自动渲染浏览器自带的 `::-ms-reveal` 眼睛图标，与 `PasswordInput` 组件右侧自定义的眼睛按钮并列并重叠（用户已截图留存）。
   * **修复方案**：在 `apps/web/src/features/settings/account/password-input.tsx` 的 `<input>` 样式中追加 `[&::-ms-reveal]:hidden [&::-ms-clear]:hidden`。
2. **UI-BUG-02 / P2：Token 仪表盘导入敏感操作缺少就地二次认证弹窗**
   * **现象**：登录超过 5 分钟后，在 `/zh/dashboard` 提交用量导入触发敏感操作保护返回 HTTP 428，界面直接暴露裸错误字符串 `reauthentication_required`，没有像账户面板一样引导用户就地输入密码与 TOTP 验证码。
   * **修复方案**：在 `packages/dashboard/src/react/imports/use-import-dialog.ts` 捕获 428 时拉起二次认证抽屉/弹窗，完成认证后自动重试提交。
3. **UI-BUG-03 / P2：设置侧边栏 Owner 分区“Docs”未适配中文**
   * **现象**：中文模式下（`/zh/settings`），“身份与受控访问”分组下方的文档分区标题硬编码显示为英文 `Docs`，其下方副标题已正确显示为 `发布总览与文档列表`（用户已截图留存）。
   * **修复方案**：在 `apps/web/src/features/settings/shared/settings-schema.ts` 中将 `label: 'Docs'` 改为 `label: isZh ? '文档' : 'Docs'`（本地已修改）。
4. **UI-BUG-04 / P2：模型热力矩阵左侧长模型名字符被遮盖/截断**
   * **现象**：在仪表盘“用量分析视图”切换至“模型热力矩阵”模式时，左侧固定列宽度不足（原设定 170px），较长模型名（如 `deepseek/deepseek-v4.1-flash-fast`）末尾字符被右侧单元格及粘性表头遮挡，显示为 `deepseek/deepseek-v4.1-flash-fas`（用户已截图留存）。
   * **修复方案**：在 `packages/dashboard/src/react/dashboard.css` 和 `model-heatmap.tsx` 中将第一列固定宽度由 `170px` 拓宽至 `220px`，并在 `[role="rowheader"]` 强化截断与完整 title tooltip 提示。
5. **UI-02 遗留 / P2：`/docs/reference` 路由跳转 404**
   * **现象**：`/{locale}/docs/reference` 当前 307 重定向至不存在的样例文章 `shell-foundations`，导致 404。
   * **修复方案**：下一版平滑重定向至对应语言的文档总览页 `/{locale}/docs`。

# Owner 账户界面四项调整

## 用户要求与结果

- 恢复码改为与敏感操作相同风格的居中弹窗：遮罩、背景模糊、标题、独立底栏；提供复制全部和明确的“已保存，继续”。弹窗期间锁定背景滚动，避免 Escape 误关一次性材料。复制失败显示页面内提示。
- 密码最小长度统一为 8 个字符：前端、API、scrypt 输入校验及受控 CLI 提示同步，原 1024 字节上限保持。登录、再认证和改密表单采用自定义校验提示，字段与错误关联，取消浏览器原生校验气泡。
- 去掉改密面板的 360px 限制，面板铺满可用宽度。宽屏新密码／确认密码双列，窄屏堆叠。
- 登录、新密码、确认密码及敏感操作当前密码增加显示／隐藏眼睛按钮，支持可访问名称与按下状态，点击不提交表单。

## [2026-10-15] 登录三步与免验完成动画

用户要求保留固定“第 x / 3 步”，免验时按顺序完成动画，而不是缩减为一／两步。普通登录统一展示账号密码、TOTP、授权确认。

- 服务端确认完成后，低风险密码登录从第 1 步依次动画到第 3 步；TOTP 完成且免独立授权时，从第 2 步动画到第 3 步。
- 独立授权仍是输入步骤，等待真正的服务端完成响应；已存在的 Owner 会话直接展示管理界面。
- 每步动画 320 毫秒，最终成功状态保留 400 毫秒，再刷新管理界面或合法返回地址。减少动态效果时立即完成。
- 已实际验证的步骤显示“已验证”，免验步骤动画后显示“已完成”。初始化绑定及恢复码保存弹窗沿用原流程。
- 新增 `owner-login-completion.tsx` 和 5 项组件测试，更新登录交互测试。相关 3 个文件共 21 项通过，Web 类型检查、相关 ESLint 通过。
- 本地浏览器核对初始“第 1 / 3 步”，三阶段均可见；截图 `.scratch/account-ui-2026-10-15/fixed-login-steps.png`。完整动画顺序由合成数据测试覆盖。

用户同时询问 Owner 一次性授权码来源：通过 `pnpm auth:owner approve --challenge <当前请求编号>` 或另一台已登录 Owner 设备签发。未替用户签发或读取真实授权码。

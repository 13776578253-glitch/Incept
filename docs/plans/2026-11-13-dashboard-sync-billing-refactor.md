# Dashboard 同步与计费重构方案

基线为 `refactor/sync-billing` 的 `171954d`。本方案确定事件身份、来源覆盖、费用版本和新模型写入的契约，并定义现有数据的迁移验收。账本的回执、可见代际、项目映射、人工审查和回滚栅栏都是迁移输入。

## 1. 事件身份

**一个逻辑事件有一个持久 ID，可以有多份观察和多个修订。** 事件 ID 用于去重和历史追溯，内容摘要用于校验观察，manifest、generation 和 batch ID 继续承担各自的同步职责。

| 对象 | 决策 |
|---|---|
| 来源会话 | 以来源及已登记的 origin 定位。原生会话 ID、设备和原有 scope 保留在来源证据里。跨设备认领沿用显式授权，一个本机路径或一个相同会话字符串不足以合并两个 origin |
| 原生锚点 | 由来源适配器交出带类型的请求、消息、用量行或计数点锚点。只有来源契约确认了作用域和重用规则的锚点才参与自动匹配 |
| 事件 ID | 首次确认时，在同一事务中写入 `(origin, anchor kind, anchor value) → event ID`。新事件可用固定规范编码和 SHA-256 派生初始 ID，已分配的 ID 由持久映射决定。锚点编码有版本，采集器升级沿用或显式桥接旧映射 |
| 观察与修订 | 保存原始来源标识、来源位置、时间及精度、模型、计数和采集证据。重复提交同一观察幂等。相同 ID 收到不同内容时，由来源的可变字段与谱系规则判定新修订或冲突 |
| 补充锚点 | 稳定别名后来出现时，将它登记到原事件。若该别名已指向另一事件，保留两边证据并进入审查。两条不同原生锚点即使时间和用量完全相同，仍分别计数 |

规范身份索引直接保存每个锚点当前绑定的事件 ID。首次绑定、补充别名及经审查的纠正，均在更新索引的同一事务中写入审计，保存旧值、新值、操作者和证据引用。纠正要求当前值与审查时的预期值一致。重试或重复观测若未改变绑定，只复用当前索引；审计日志用于追溯有效变更，读取身份直接查索引。

用量值、模型名和别名、项目名、价格、文件绝对路径、文件 mtime 与本次采集时间都属于事件内容或观察证据。它们可以变化，事件 ID 持续有效。文件字节范围及摘要证明轮换和保留关系。缺可信时间时保留未知时间及原因，具备日粒度证据时只记日期。日期窗口单列未能归日的量。

- **Codex** 的计量单元是已验证的累计点差值。用源内有序点及经验证的日志段继承关系锚定，保留前序点、原始累计值和独立用量证据。当前 `pointKey` 按会话加时间生成，迁移保留它作为旧引用。时间相同的点须用来源证据区分。计数回退、缺开头或不明轮换进入隔离或审查，缺失前缀仍可作为未归属量记录。
- **CommandCode、Claude Code、Gemini CLI** 优先使用来源提供的请求或消息 ID 及会话作用域。缺 ID 时，可在已验证保留的同一日志段内使用位置锚点。文件改名、重新编号和整段重写需先证明位置继承。
- **Antigravity、OpenCode、ZCode** 优先使用已验证的原生用量键。Antigravity 现有稳定键集合证据继续适用。OpenCode、ZCode 的键稳定性、重用和修改语义分别验证后，才启用集合替换。
- **DeepSeek Harness** 保留响应、消息和压缩摘要等不同类型的锚点，验证父会话与 seed 的继承。首次只有响应 ID，后来出现消息 ID 时登记为同一事件的别名。候选别名的排序变化不触发重编号。
- **aiusage、ccusage 和旧导入** 保留索引行、日报或原始批次成员自己的身份。内容指纹用于找候选。跨格式替换要求作用域和粒度相容，并且正反方向都唯一。多对一日报保留为独立聚合证据。同一片段内日报与已识别事件的重叠量无法验证时，保留当前可见版本并记录待对账差异。

保留旧 `eventId`、`pointKey`、`nativeKey`、批次及成员位置与新 ID 的映射。已有 v2 manifest、哈希、回执和 Agent outbox 按原契约校验。新身份先落在旁路索引。若以后改线上协议，再独立协商版本和迁移 outbox。

## 2. 来源覆盖

**覆盖是来源对一个明确片段的声明。** 一个采集结果可以有多个片段，同一会话可以同时有完整前缀和缺失后缀。

| 字段 | 约定 |
|---|---|
| 范围 | 来源、origin、会话、适配器版本与读取依据。日志用逻辑段和半开位置区间，数据库用经验证的键域和一致性快照，日报用来源声明的时区及半开日期区间 |
| 状态 | `complete` 表示指定范围扫描和校验完成，允许明确的零事件。 `partial` 带已证明片段、缺口和原因。 `unavailable` 表示当前取不到来源。 `failed` 保留失败阶段和错误类别 |
| 证据 | 按来源保存前缀摘要、边界或键集合承诺，附记录数、读取时点、schema 或解析版本。回退数据带实际来源及时间精度 |
| 合并 | 完整证据只替换它已覆盖且匹配成功的成员。局部损坏时保留上一代或历史索引里其余可证明的部分。同一范围的重叠身份不清时交给审查，保留旧 head |

追加日志验证已保留前缀和本轮末端。SQLite 在一致性快照上核对键集合，明确区分表结构变化、状态变化和用量修改。日报只声明日粒度覆盖，整个会话的覆盖不能由日报或存在 session header 推导。每次采集先限定授权来源再枚举，读取、解析和解压预算按来源计算，局部失败留在对应范围。

项目归属同样保留证据。可用的来源元数据或显式映射写入项目键，缺字段时归到未归属。个人目录映射通过私有配置迁移。已有明确映射沿用，旧硬编码归属的修正逐条留差异。

## 3. 费用历史

**用量与费用各自版本化。** 同一个事件的 Token 修订可以触发新的费用计算。改价只产生新的计价结果和版本记录。

| 状态 | 持久字段与规则 |
|---|---|
| 实际记录费用 | 原金额、币种、来源及观察修订。显式零保留为零。是否已含峰谷或其他倍率由来源契约说明，证据不足时标记金额语义未知 |
| 参考估算 | 用量修订、精确计价键、费率版本、适用时点、规则版本、币种和计算结果。费率按输入、输出、缓存读写和推理等计量项配置，重复计数与分项关系由来源契约定义 |
| 未定价 | 保存事件和可用的 Token，金额为空，记录未知模型、费率缺项、未知时点、身份冲突等原因。覆盖统计保留未定价 Token |
| 迁移冻结值 | 保存旧页面可重现的金额、口径与证据摘要。历史若缺费率来源，标记为旧口径估算，保留证据不足状态 |

费率与计价结果采用可精确运算的十进制表示，计算和累加保留精度，统一到展示边界舍入。不同币种分别合计。峰谷时间、时区、节假日表及倍率随规则版本生效。只有已明确是基础价的项目参与倍率计算。费率选择用事件发生时间，日期摘要只有在整个可能时间段适用同一费率和倍率时才自动计价。

首个可见费用版本在账本旁路持久化。历史对账用冻结的旧目录、别名、规则、时区和观察截止时间生成基准。若之后决定补价或纠错，用显式重估批次输出影响范围、逐项差异及回溯版本，再发布新版本。页面读取已发布费用版本，接收端实时配置变化通过发布流程生效。

## 4. 新模型与费率发布

**首次见到新模型时，先提交用量和未定价原因。** 识别键包含计费渠道、可验证的服务商和原始模型标识。展示分组可以把模型放在同一族，计价保留版本及渠道差别。信息不全时保留来源给出的原始标识，等明确证据补齐。

1. **登记模型候选。** 同一未知模型键重复到达时，只更新发现次数和最近观测，保留首见信息。设备随包提供的价格作为候选证据。
2. **发布明确费率。** 在接收端登记精确计价键、证据出处、费率各项、币种、生效区间和规则版本。别名是单独的显式映射，限定计费渠道与作用时间。同名后缀、厂商优先表及压缩 JavaScript 正则所得目录都无法独自发布正式费率。
3. **事务固定版本。** 校验计价键和生效区间，禁止同键区间重叠、别名循环、缺必需字段及非法费率。按规范编码生成版本摘要。相同版本重复发布返回既有结果，摘要冲突报错。结算与发布使用一致性读，重试复用已固定的费率版本和结算键。
4. **处理迟到事件和历史补价。** 新进入账本的迟到事件按它的发生时间查已发布版本。已入账但未定价的历史保持原状态，等明确发起重估才补价。替换费率关闭旧的有效区间并发布后续版本，旧结算仍能重放。

因此，同一 Codex 或 CommandCode 会话先上传模型 A，再新增模型 B 时，两者各自解析和固定费用版本。B 暂时缺价只影响 B，A 的旧费用与已提交 Token 都保持稳定。当前把整个父代 `basis` 继承给新代际的协议，继续由兼容层解释，新的费用明细按事件保存。

## 5. 迁移和验收

现有 `shadow-check` 会先向目标库迁移 v1 批次，再比较 `7d`、`30d`、`all`。切换脚本按同样三个窗口要求全量相等。这次使用独立副本跑旧命令，新增的验收工具还要核对 `14d`、逐事件身份、旧历史可重放性以及有依据的修正差异。

| 阶段 | 动作 | 通过条件 |
|---|---|---|
| A. 冻结基线和恢复演练 | 从一致性副本读取 v2 ledger、仍参与读取的 v1 批次库、Agent heads/outbox 和定价配置。记录源库身份与 revision、旧批次 checksum/状态、回执与可见 head、价格规则摘要、观察时间和时区。用专用目录恢复验证 | SQLite `quick_check` 通过。关键库、账本头、回执和未完成批次与基线清单一致，源文件保持只读 |
| B. 可恢复回填 | 在独立库或加法旁路表中回填身份映射、覆盖证据和费用记录。每批在同一事务保存数据、游标和输入指纹。保留审查、回滚、已隔离及旧审计引用。历史证据缺失时记录不可重放及原因 | 中断后续跑、重复回填及重放收据都不新增重复事件。源记录逐条有已迁移、已证实重复、保留旧口径或待审处置。当前可见的待审记录仍可沿用原可见结果 |
| C. 双轨对账 | 对同一个固定基线，先跑旧口径复现，再打开归属、身份和定价修正。按来源、设备、会话、项目、模型、日期和四个窗口对照 | 旧口径事件与可见状态逐项对应，整数 Token 分项差为零，费用按冻结规则重放。修正模式每条差异有旧值、新值、原因、证据和决定记录，未解释差异为零 |
| D. 并发与故障演练 | 在副本注入并发上传、读切换、网络丢回执、Agent 重启、部分采集、SQLite WAL、定价发布和数据库恢复 | 账本仍只有一个权威写入路径。上传重试幂等，旧 revision 的快照无法盖过新发布。恢复到较低 revision 时客户端按新数据集版本接收数据，陈旧结果显示实际年龄和状态 |
| E. 灰度读取 | 新投影先在后台对照，接着切 Owner，最后切 Pro/Guest。发布时记录源库身份、账本 revision、计价与映射版本、快照生成时间、读模型版本 | 各角色读取的字段符合现有权限，发布 generation 内的窗口一致。资源和延迟对照同机、同数据量的旧版基线。先测定允许的回填时间、峰值内存、队列等待与页面延迟，再签署正式切换条件 |

切换前冻结迁移涉及的映射与费率变更，按最后一个共同 revision 追平旁路。报告绑定输入摘要和目标版本，输入漂移后重新对账。正式切换要分别记录代码版本、读取开关、投影进度、写入协议以及最后一个可回退的 revision。

逐事件差异报告至少含旧引用、新事件 ID、旧新可见状态、各 Token 分项、旧新费用与币种、价格版本、归属和原因。按窗口输出未定价、未归日、待审和隔离量，并分别统计增加和减少，避免相互抵销。费用基线保留旧计算输入与舍入方式，按旧展示精度逐窗口复现。换用十进制后的舍入差单列核对，实际记录费用按原精度对账。

**先切读，再考虑切写。** 首轮使用现有账本写入与 wire 协议，旁路按提交游标读取或补齐已提交记录。读取回退只切回旧投影，保留切换后已经提交的用量和回执。以后若启用旧版本无法读取的写协议，必须先演练该版本的接收端回退或保全新写入的重放路线。仅在停写并完成尾部记录和 outbox 对账后，才允许从备份恢复账本。

## 6. 实施边界

第一批先实现身份映射、范围契约和可重复的迁移对账夹具。第二批实现版本化费率和费用投影。第三批让 Web 消费新的已发布快照，并在灰度验证后逐步退出旧 fallback。目录按来源适配、事件与费用契约、同步账本与旧版兼容、查询投影拆分。Web、Agent 和 Gateway 用明确的包导出调用这些模块，现有协议和数据库路径由兼容层维护。

真实数据量、生产副本演练结果和性能阈值随实施记录补齐。

### 身份回填演练入口

先用现有 `backup` 命令生成独立账本副本。构建维护工具后，以该副本为 `--source`，以全新旁路数据库为 `--output` 执行：

```text
node packages/dashboard/dist/sync-maintenance.mjs backfill-usage-identity --source=<账本副本绝对路径> --output=<旁路库绝对路径> --limit=1000
```

重复执行到 `complete: true`。扫描阶段先保存成员和覆盖证据，确定全部冲突后，再分批物化唯一绑定。`scanComplete` 表示冲突扫描结束，`bindingsWritten` 表示本次新增绑定，最后一批返回 `seen`、`mapped`、`unproven`、`conflicts` 和 `history`。早期版本生成的旁路库应以新输出路径重跑。

用 `usage_ledger_identity_disposition` 查看逐成员结果，用 `usage_identity_conflicts` 查锚点碰撞。冲突及缺锚点成员保留原引用，碰撞锚点不产生规范绑定或有效变更审计。覆盖记录包括零成员可见代际和已接受审查的可见祖先引用。历史验收表保留已迁移的 v1 批次及成员、投影、隐藏及回滚代际的父链和变化、审查及其成员引用。逐版本金额对账由后续计费批次完成。

已用归档的 Phase 0B 生产审计副本（revision 843）跑完整轮回填。54,475 个可见成员中，52,830 个可映射，1,645 个由 aiusage 读取的 Antigravity 成员缺少锚点，碰撞为零。保留 356 个隐藏代际、31 条审查及 28,191 个审查成员，11 个可见 scope 的祖先链关联 22 条已接受审查。未发现缺失观察或 manifest。再次执行的新增绑定为零。该副本没有 v1 批次和已回滚代际，这两类路径由合成回归覆盖。分来源的可映射量为 Antigravity 25,829、Codex 15,020、DeepSeek Harness 6,672、CommandCode 4,980、OpenCode 215、Claude Code 67、ZCode 41、Gemini CLI 6。

### 版本化计费演练

在同一个已完成身份回填的旁路库发布目录，再生成有独立名称的计费批次。所有路径使用绝对路径。

```text
node packages/dashboard/dist/sync-maintenance.mjs publish-usage-rates --sidecar=<旁路库> --catalog=<目录JSON>
node packages/dashboard/dist/sync-maintenance.mjs build-usage-billing --source=<原账本副本> --sidecar=<旁路库> --baseline=<基线JSON> --run=<批次名>
```

目录 JSON 使用 `{ rates, close? }`。费率包含规范 `model`、`provider`、固定为 `USD` 的 `currency`、`evidence`、毫秒时间 `effectiveFrom` 与可选 `effectiveTo`、十进制字符串 `perMillion`。首次见到的新模型按缺价原因归集在 `usage_unpriced_models`。需要峰谷的价格可提供规则版本及不重叠的 UTC 区间，区间外使用基础价。发布新费率时可在同一事务用 `close: [{ version, at }]` 关闭旧开放区间。重复发布相同版本可重入，冲突使整次发布回滚。旧账本随设备上报的数值价格继续作为旧口径输入，并在新版旁路库保存为审计记录。

基线 JSON 使用 `{ checkedAt, rates, aliases }`，其中 `rates` 和 `aliases` 是旧读取路径实际使用的接收端费率与别名，`checkedAt` 为冻结的毫秒时间。工具从原同步库只读获取 v1 批次的费用、映射、可见性和认领证据。账本、身份审计或目录版本变更后，重估使用新批次名，旧明细和费率版本保留。

费用明细按 `(批次, 成员类型, scope 或导入批次, 位置, observation)` 唯一存放。已映射事件另存规范 ID。缺锚点、碰撞和 v1 成员仍逐条保存 Token、旧费用、项目及新计价状态；重复观察按旧可见成员的实际位置对账。历史 v2 数值金额缺币种时保留原额和未知币种状态。普通身份纠正可以迁移已绑定的别名，隔离锚点的解封和人工消歧留给单独操作流程。

revision 843 的本地演练生成了 54,475 条费用明细，包含全部 1,645 条缺锚点成员。该轮使用空的接收端基线与新版费率目录，6,840 条保留来源记录金额，47,635 条为未定价。该次运行用于验证成员完整性。合成 v1 导入夹具以冻结的接收端费率核对四个窗口的 Token 和旧金额。生产真实 v1 与已回滚代际组合、费率来源审查和灰度切读仍需单独验收。

### 切读前验收补充

- 旧基线费率键和别名键按旧 Dashboard 的规则去首尾空白并转小写。同一规范键有不同值时拒绝输入。新版费率仍按精确模型匹配，版本摘要只包含约定字段。
- 时段倍数支持正十进制值，包含折扣。已知日精度的用量按 Dashboard 的 UTC+8 日界限核对整日费率和倍数。出现日内变化时保留用量并标记未定价。原 v1/v2 记录自身缺少时间精度字段时，沿用现有的事件时间解释，不能从时间值推断其为日报。
- 核账摘要区分索引成员数、参与核算的当前和旧导入成员数、截止时间外及零 Token 的跳过数。每个窗口单列币种未知的来源费用笔数。
- 隔离锚点可由 Owner 在旁路库执行 `resolve-usage-identity-conflict`。决议文件包含 `origin`、原 `anchor` 与完整的 `members` 清单。每个成员提供 `scope`、`position`、`observation` 与有来源证据的 `replacement`。命令校验全部成员和替换锚点，原子写入新绑定及审计；碰撞旧锚点继续隔离。旧计费批次仍保存决议前的结果，重估使用新批次名。

```text
node packages/dashboard/dist/sync-maintenance.mjs resolve-usage-identity-conflict --sidecar=<旁路库绝对路径> --decision=<决议JSON绝对路径> --owner-confirm=I_AM_THE_OWNER --reason=<证据说明>
```

组合演练从归档的真实 v1 导入库迁入一份有效批次和一份已回滚批次，再对隔离的 revision 843 副本执行一次 v2 代际回滚。演练库到达 revision 846，历史旁路保留 2 个 v1 批次、7,951 个 v1 成员和 1 个已回滚 v2 代际。计费明细包含 54,475 个 v2 可见成员及 7,944 个可见 v1 成员，共 62,419 条。本轮验证可见性与成员数。

将归档旧覆盖配置用于 revision 843 的对照运行时，四个窗口的 Token 与空基线运行一致，全量旧金额由 791.755555983196 变为 1,260.7328740932082。两次均保留 54,475 条明细。空新版目录下，47,635 条未定价记录归入 32 个渠道、模型与原因组合。revision 843 保留作历史重放和回归基线。金额验收改用灰度目标环境的一次同版本采集，同步归档账本快照、接收端费率及覆盖配置、截止时点和旧 Dashboard 四窗口结果。

按[官网 API 等效成本契约](./2026-11-14-dashboard-billing-contract.md)维护规范模型映射、USD 费率版本、审计原额与覆盖率。历史调查结果保留在[渠道对账汇报](./2026-11-14-dashboard-billing-channel-review.md)。`build-usage-billing` 默认使用[渠道映射](../../packages/dashboard/src/sync/usage-billing-channel-mappings.json)，可通过 `--channel-mappings=<绝对路径>` 提供完整替代文件。解析后的规则随新批次存档。更新费率或映射时使用新 `--run`。

### Owner 灰度读取

用灰度目标环境的同版本快照完成四窗口对账，并在隔离旁路库生成待审报告。报告包含四窗口基线、USD 估算与覆盖率明细、待审未估算分组和费率审阅摘要。币种未知的来源金额分组供审计。

```text
node packages/dashboard/dist/sync-maintenance.mjs review-usage-billing-read --sidecar=<旁路库> --run=<批次名> --report=<待审报告JSON>
node packages/dashboard/dist/sync-maintenance.mjs publish-usage-billing-read --sidecar=<旁路库> --run=<批次名> --approval=<验收JSON> --output=<新发布JSON> --owner-confirm=I_AM_THE_OWNER --actor=<操作者标识> --reason=<发布原因>
```

验收 JSON 绑定 `input`、`revision`、`ledger`、`asOf`、`catalog` 和 `pricingReviewDigest`。`windows` 填写同期现网采集的四个 `{ range, tokens, baselineCost }`，`baselineEvidence` 填写来源。`pricingEvidence` 引用对生产 USD 费率及待审未估算分组的审核结果。命令核对四个窗口数值和审阅摘要，空费率目录或目录变更均拒绝发布。先发布到新文件，再将 Web 配置指向已发布文件。

默认关闭。灰度环境设置 `INCEPT_BILLING_READ_MODE=owner` 和 `INCEPT_BILLING_PUBLICATION_FILE`，由 Owner 访问 `GET /api/dashboard/billing?range=14d`。接口响应包括 `asOf`、十进制字符串 `estimatedCostUsd` 及三个覆盖率 Token 计数 `estimatedTokens`、`unpricedTokens`、`excludedTokens`。审计计数 `recordedUnknownCurrency` 仅用于核对历史原额留存。使用新版计费契约的批次生成 v2 发布件。

发布文件的 `approval` 区保存 CLI 填报的操作者标识、发布原因、发布时间、两项证据引用及费率审阅摘要。Owner API 仅返回汇总字段。早期生成的无审计发布文件需要重新发布。证据字段填写归档引用，避免写入凭据。

API 验收后可额外设置 `INCEPT_BILLING_UI_MODE=owner`，在 Owner 的概览主费用卡和费用区读取新版快照。同步 revision、可见谱系或旧导入状态变化时接口返回 503，页面显示快照暂不可用。撤回 UI 试读时关闭 UI 开关，撤回 API 试读时关闭读取开关。趋势、模型和项目费用明细将在取得同口径聚合后单独迁移。开启真实环境试读前需完成 `pnpm build`、同期四窗口对账和目标目录审核。持续使用前需建立后台重估与发布机制。
